# NNI-Test

Documentation folder. This file describes Microsoft NNI (Neural Network
Intelligence) at a high level. It is reference text only. There is no code
here.

## What NNI Is (High Level)

Microsoft NNI is an open-source AutoML toolkit. It automates the search and
optimization part of machine learning. It covers four main tasks:

- Hyperparameter tuning
- Neural architecture search (NAS)
- Feature engineering
- Model compression

NNI runs on top of your normal training code. It works with PyTorch,
TensorFlow, and similar frameworks. It starts and controls many trial runs
across local and remote computers. It finds better models with little manual
work.

NNI is written for Python users. You install it with pip. It uses the MIT
license. This means it fits normal research and production work. You can also
change it and embed it in your own systems for free.

If you already write your own sweeps or NAS scripts, NNI is a ready-made
framework. It sets one standard way to run experiments, send work to compute
resources, and watch the results.

## Core Concepts and Architecture

NNI is built around two ideas: experiments and trials.

- An experiment is one full optimization run. Example: "tune this ResNet on
  CIFAR-10 for 200 trials using TPE."
- A trial is one training run with one set of hyperparameters or one chosen
  architecture.

Inside NNI, the main parts are:

- NNI Manager. The central controller. It manages the experiment, talks to
  training services, and controls the trial lifecycle.
- Training service. The backend that knows how to start trials on different
  compute setups. These include: local machine, remote SSH servers,
  Kubernetes (AKS, Kubeflow, FrameworkController), Azure ML, DLWorkspace,
  AdaptDL, and more.
- Tuner / NAS / Compression modules. Plug-in algorithms for hyperparameter
  search, neural architecture search, and pruning or quantization.
- Web portal (WebUI). A built-in interface to watch experiments live, see
  metrics, open trial details, and control runs.

This modular design lets you swap parts without rewriting your training
script. You can change a Bayesian tuner for random search. You can move from
local runs to AKS. You only change the config file.

## Major Features (From an ML Engineer's View)

NNI targets these key capabilities:

- Hyperparameter optimization. It gives you many search algorithms: random,
  grid, TPE, evolution, and others. You define a search space in JSON or YAML.
  Your training code calls NNI's API (for example, get_next_parameter) and
  reports metrics back. NNI then drives the search loop.
- Neural architecture search (NAS). It supports frameworks like Retiarii. You
  define a search space over model structures. NNI samples candidate
  architectures and tests them.
- Model compression. It gives tools for pruning and quantization. These shrink
  models while keeping accuracy. The work runs inside the same automated search
  framework.
- Feature engineering automation. You can search over feature changes and
  selections as part of AutoML pipelines.

For day-to-day use, NNI also gives:

- A CLI called nnictl. You use it to create, stop, and manage experiments from
  YAML configs.
- A Web UI. It runs at a local or chosen address (for example,
  127.0.0.1:8080). You use it to see metrics, trial history, and search
  progress.
- Ready examples. For example, MNIST with PyTorch. After install, you can start
  one directly with: nnictl create --config ...

## Supported Environments and Workflow

NNI supports Ubuntu, macOS, and Windows. The main requirement is Python 3.6 or
newer, 64-bit.

Install is one command:

    pip install nni

The normal workflow is:

1. Define an experiment config. This sets the search space, tuner, training
   service, concurrency, and more.
2. Change your training script so it pulls parameters from NNI and reports
   metrics back.
3. Start the experiment with nnictl. Then watch it and adjust it in the Web UI.

Training services let you scale from one host to clusters and cloud setups. You
do not rewrite your core training code. You mostly update the config to point
at Kubernetes, Azure ML, or remote servers.

## Repository Layout (this folder)

This folder extends the NNI reference above with a working proposal + training
pipeline:

- `proposals.jsonl` — proposed **models** (architecture + layer dimensions only;
  no training settings). Generated by `gen_proposals.py`.
- `verify_proposals.py` — literature-grounded logical verification + live
  citation checks. See `VERIFICATION.md`.
- `pipeline/` — `build_model.py` (spec → torch), `smoke_test.py` (compile gate),
  `run.sh` (gen → verify → smoke).
- `tests/test_mnist.py` — real-data MNIST test for the MNIST family.
- `PROPOSALS_SCHEMA.md` — the proposal schema and invariants.
